Three related APIs: pluggable RAG, enterprise retrieval, and retrieval chat

How to view diagrams: open this file in Chrome/Edge. If Mermaid does not load from file://, run python -m http.server 8765 in docs/diagrams and open this page via http://localhost:8765/.

Security note: In the current codebase, POST /api/v2/rag/query does not use Depends(require_role(...)) unlike the two /api/v2/retrieve/* routes. If your deployment expects admin-only access for all query paths, gate /api/v2/rag at the proxy or add an auth dependency in rag_api.py.

4 — File-level workflow: POST /api/v2/rag/query

  • app/main.py — include_router(rag_router, prefix="/api/v2/rag")
  • app/api/v2/rag_api.py — rag_query: _validated_tenant → RAGRuntimeContext → scan_text → pipeline_factory.get_cached or get_client_config + pipeline_factory.build → optional prompt template _resolve_prompt_template → pipeline.query(..., runtime_context=) → _shadow_dual_execute (optional) → RAGQueryResponse
  • app/core/pipeline_factory.py — PipelineFactory.build, cache, AssembledPipeline.query delegation
  • app/core/rag_pipeline.py — RAGPipeline.query: config merges, optional node PII, retrieval executor or legacy inline path, embed → search → rerank → context → LLM → trust
  • app/core/config/client_config_resolver.py — get_client_config, fingerprints
  • app/core/config/client_config_schema.py — ClientConfig
  • app/utils/tenant_validator.py — validate_tenant_id
  • app/middleware/security_middleware.py — scan_text
  • app/utils/pipeline_logger.py — structured logging
  • app/core/runtime/runtime_context.py — RAGRuntimeContext
  • app/core/configs/prompts/*.json — optional system prompt templates
  • app/core/migration/migration_controller.py — shadow dual execution flag (used by _shadow_dual_execute)
  • Concrete adapters: app/core/vectordb/*.py, app/core/embedders/*, app/core/rerankers/*, app/core/llms/* (selected at factory build time)

5 — File-level workflow: POST /api/v2/retrieve/query

  • app/main.py — include_router(retrieve_router)
  • app/api/v2/retrieve_api.py — retrieve_query: require_role("admin") → strict tenant + storage UUID → resolve_config_or_fail / resolve_runtime_components* → intent map → scan_text → optional HyDE (inline LLM) → _embed_in_thread → RetrievalRepository (with _get_pipeline when authoritative) → RetrievalRuntime.retrieve → repository.close() → BM25/RRF → reranker_registry → threshold → ResultItem list → optional answer branch with context scan_text → RetrieveResponse
  • app/retrieval/components.py — RuntimeComponents, legacy env fallback
  • app/retrieval/repository.py — fetch_candidates, DB + vectordb hydration
  • app/retrieval/runtime.py — policy, scoring, ranking
  • app/retrieval/policy.py / scorer.py / explain.py — governance and explanations
  • app/services/ingestion/ingestion_service_v2.py — get_embedder, _get_pipeline
  • app/core/search/bm25_index.py / rrf_fusion.py — optional hybrid reorder
  • app/core/plugin_registry.py + app/core/rerankers/register.py — reranker plugins
  • app/frontend-admin/app/dashboard/retrieve/page.tsx — primary UI caller

6 — File-level workflow: POST /api/v2/retrieve/chat

  • app/main.py — same retrieve_router registration as retrieve/query (retrieve_chat_api shares prefix)
  • app/api/v2/retrieve_chat_api.py — chat_retrieve: require_role("admin") → intent → strict tenant + storage UUID → resolve_config_or_fail → _resolve_llm for rewrite+answer → scan last user message → _rewrite_query (if multi-turn) + scan rewrite → optional HyDE → _embed_in_thread → same RetrievalRepository/RetrievalRuntime.retrieve as retrieve/query → reranker (with per-request override) → BM25/RRF → threshold → build ChatResultItem → optional LLM answer with context scan → ChatRetrieveResponse
  • All retrieval stack files listed in §5 apply equally here after the chat-specific prologue
  • app/frontend-admin/app/dashboard/retrieve/chat/page.tsx — UI for multi-turn chat
  • app/frontend-admin/lib/apiRoutes.ts — documents both CHAT and RAG.QUERY paths

7 — When to use which

/api/v2/rag/queryUse when you want the single packaged RAG pipeline (factory-built, config-complete): one call for embed → retrieve → rerank → answer with pipeline-internal trust and timing breakdown. Best for integrations that mirror how RAGPipeline is documented. Ensure you are comfortable with the current auth posture or add guarding.
/api/v2/retrieve/queryUse for admin retrieval debugging: intents, rich trust/signal explanations, optional hybrid/rerank ordering, retrieval without LLM (generate_answer=false), strict tenant enforcement aligned with ingestion UUIDs.
/api/v2/retrieve/chatUse for multi-turn conversational RAG in the admin UI: history, query rewrite, per-turn model/rerank overrides, LLM on by default, session id for the client.
