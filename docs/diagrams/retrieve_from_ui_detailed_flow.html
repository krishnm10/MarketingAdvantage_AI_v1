Enterprise retrieval from admin UI — detailed numbered flow

Scope: Dashboard retrieve page app/frontend-admin/app/dashboard/retrieve/page.tsx → POST /api/v2/retrieve/query in app/api/v2/retrieve_api.py. Concurrency: Request is handled synchronously in the API process (no Celery queue for this path). PDF: Print from Chrome/Edge. If Mermaid fails on file://, run python -m http.server 8765 in this folder.

Config authority at query time:
resolve_config_or_fail(client_id) in app/retrieval/components.py calls get_client_config (client_config_resolver.py). On success, resolve_runtime_components(ClientConfig) yields frozen RuntimeComponents (embedder/vectordb/collection/LLM/reranker defaults from JSON).
Legacy fallback: If resolution fails and ENABLE_LEGACY_ENV_FALLBACK is truthy (or client_id == "default"), resolve_runtime_components_legacy() uses env vars such as MAI_EMBEDDER, MAI_VECTORDB, MAI_COLLECTION, MAI_RERANKER.
Vector DB handle for search: When mode is authoritative_config, the API builds RetrievalRepository(db_session, vectordb=_pipe.vectordb, collection=rc.collection) using _get_pipeline(retrieve_cid) from ingestion_service_v2.py so search uses the same vectordb instance as the merged config. Otherwise RetrievalRepository(db_session=db) alone (legacy path in repository).
Query embedding: _embed_in_thread → _embed_query → get_embedder(business_id) → _get_ingestion_pipeline(business_id) (ingestion-grade embedder only; matches indexed vectors for that tenant).
Security (query-time): Before any external call (embedder / LLM), security_middleware.scan_text(req.query, context="retrieve_query"). Injection → HTTP 400. PII → redacted_text drives embedding (and HyDE builds on original question text in prompt but replaces embed_text with hypothetical answer when HyDE succeeds).
Context before LLM: When generate_answer is true, concatenated chunk text is scanned again with context="retrieved_context"; redacted text is passed in the RAG prompt.
